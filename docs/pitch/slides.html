Remember

Fifteen seconds. Remember has two layers. The bottom layer is a bench that makes every forgetting experiment comparable: one frozen model and data stream, techniques as plug-ins, one GPU per run on Modal, and a pre-registered analysis. The top layer is a research agent that uses the bench to study why the model forgets. Layer 1 · Phase 1: the bench

One frozen bench. Twenty minutes a run.

What we tested

Six published techniques: replay, learning-rate re-warming, LoRA, layer freezing, distillation, weight averaging. 

Several alone, and 14 in combination.

The run

Gemma 3 1B trains on code, then on legal text: 10 million tokens of each, the same stream every run.

Did it learn?

Perplexity on held-out text from the new domain, right after training on it, divided by the base model’s. Below 1 means it learned.

Did it forget?

Change in accuracy on four multiple-choice tasks, 500 questions each, against the model before training: ARC-Easy, HellaSwag, PIQA, PubMedQA.

Twenty-five seconds. We hold everything constant. One small model trains on code and then on legal text, the same stream every run, and a run takes about twenty minutes, so we can afford many. Two scores. What it kept: accuracy on four general multiple-choice tasks, two thousand questions in all, compared with the model before training. What it learned: perplexity on held-out text from the new domain, measured right after training on it, relative to the base model. Six published techniques plug in as switches; we ran several alone and fourteen combinations, and we pre-registered what counts as a win. If asked: the questions are split into a selection half and a report half so we never pick and report on the same items. Legal is where learning shows; the model already knew code-like text well, so its code perplexity did not improve. Twenty-five seconds. First we re-tested six published claims on the one bench, with the same model, data and budget for each. Two reproduced: the standard recipe of replay plus learning-rate re-warming does beat no fix, and the peak learning rate is the main knob. Three did not: replay alone, distilling on the replay tokens, and freezing the top half instead of the bottom. One reproduced in part: LoRA does forget less and learn less, but its rank claim only held once we tuned its learning rate. A failed reproduction at our small scale is not proof the paper is wrong, and we say so.

Twenty-five seconds. The second layer is the research agent, which studies why the model forgets. Each hypothesis states a prediction before any run. Code decides what is allowed to run and a fixed rule gives the verdict, so the model never grades itself. Across four instances it proposed 108 hypotheses, 14 were refused, and 208 runs tested the rest. Thirty-two of the tested configurations were techniques the agent wrote itself, each passing a syntax check, a tiny-model check and a short GPU probe first. Its skeptic step re-runs every confirmed result at two more seeds and tests the cheapest alternative explanation. Nine held. Two were knocked down by its own checks.

Twenty-five seconds. Two things came out of it. First, a lead that held at four seeds: with the same distillation and the same amount of legal learning, putting the new knowledge in separate adapter weights lost 15 percent of the most fragile questions, against 69 percent on the full weights. Second, a story that did not hold. The agent first concluded the damage sits in the MLP blocks, because a technique it wrote to protect them kept most of the fragile questions. Its skeptic step then asked the cheap question: would plain slower training do the same? It did better, 14 percent lost against 23, while learning more legal text. So that protection came from adapting less, not from where. The agent caught its own mistake. Caveats if asked: the first lead is scoped to one learning rate; the fragile questions are defined by full-weight runs, which makes full-weight arms look worse on them.

Twenty seconds. The takeaway: on this bench, tuning the learning rate matches or beats every published technique we tested, so any new fix should be judged against that. And we have three leads, which we would pursue with the same agent, because each is a hypothesis with a prediction that the bench can test in twenty minutes. One: separate weights protect old knowledge; does that hold over many domains? Two: is the damage in particular layers, tested fairly? Three: seeds lose the same questions and pick the same wrong answer; can we predict which, before training? The limits are real: one small model, a short stream, and no winning technique yet.
